# apps/web 规则

## 1. 适用范围

本文件适用于 `apps/web` 目录下的前端应用代码。

涉及 `apps/web` 改动时，除遵守根目录 `AGENTS.md` 外，还必须遵守本文件。

## 2. 技术栈与职责

- 技术栈：Vue3 + Vite + Vue Router + TanStack Vue Query + meri-plus + Tailwind CSS
- 主要职责：页面路由、页面级状态、表单交互、前端请求封装、页面级业务组件

## 3. 代码组织要求

- 页面路由逻辑放在 `apps/web/src/routes` 附近。
- 通用请求封装放在前端应用的 `lib` 或类似基础层，不把网络请求散落到页面组件中。
- 页面级状态、表单逻辑、数据请求逻辑应尽量靠近使用点组织。
- 业务页面组件留在 `apps/web`，不要提前抽入共享包。
- 当前项目已采用 `src/routes`、`src/lib` 的目录分层，新增代码应优先沿用该结构。
- 组件优先使用 `meri-plus`；若新增业务组件或业务组合组件，应优先放在页面附近或 `src/components`，不要提前抽共享包。

## 4. 组件边界

- 通用基础组件优先来自 `meri-plus`。
- 只服务单个页面或单个业务流程的组件，保留在 `apps/web`。
- 不要让页面组件直接依赖不稳定的后端返回结构，必要时增加映射层。

## 5. 数据与租户约束

- 不在前端硬编码核心业务租户决策。
- 不绕过 `packages/api-contract` 直接手写接口结构。
- 不因为图省事把后端字段兼容逻辑散落在多个页面中，应尽量收敛到请求层或映射层。
- 涉及租户请求头、租户上下文时，优先复用 `packages/shared` 中的常量与类型。
- 当前项目已在 `src/lib/api.ts` 中统一通过 `TENANT_HEADER` 传递租户信息；后续新增接口应优先复用同一请求入口或相同模式。
- 登录、健康检查这类已有接口调用应继续通过契约 schema 做响应校验，不要跳过 `zod` 解析直接信任后端返回值。

## 6. 配置与共享依赖

- 共享环境变量配置优先通过 `@app/config` 消费，不在前端重复维护同义配置。
- 仅前端使用的运行时配置，保留在前端应用自身。
- 前端专属业务逻辑不得放入 `packages/config` 或 `packages/shared`，通用 UI 基础组件保留在 `apps/web/src/components/ui`。
- 当前前端接口基地址来源于 `VITE_API_BASE_URL`；后续新增请求配置时应继续通过 Vite 环境变量注入，不要在页面中硬编码服务地址。

## 7. 注释要求

- 导出的 hooks、请求封装、类型转换函数、复杂表单逻辑、兼容逻辑优先补充 `JSDoc`。
- 页面级临时注释应聚焦“为什么这样做”，不要重复 JSX 或函数调用的表面含义。
- 对 Vue 表单状态、契约校验、`useMutation` 这类组合式流程，若存在默认值、租户透传、错误映射等隐式约束，应用 `JSDoc` 说明。

## 8. 推荐验证

- 类型与构建验证：

```bash
pnpm --filter @app/web typecheck
pnpm --filter @app/web build
```

- 如果新增或修改了前端测试，也应补充：

```bash
pnpm --filter @app/web test
```

## 9. 禁止事项

- 禁止把页面逻辑、路由逻辑塞进共享包。
- 禁止在多个页面重复手写相同接口类型。
- 禁止以前端条件判断替代真正的后端租户隔离。
- 禁止绕过 `src/lib/api.ts` 风格，在页面组件中直接拼接带租户头的 `fetch` 请求。
